1"""Verify HTTPS against the OS trust store by default. 

2 

3``requests`` verifies against the bundled ``certifi`` set, which lacks 

4internal/corporate root CAs and TLS-proxy certs. Because APM also shells out to 

5``git`` (which reads the OS trust store), ``git clone`` of an internal host 

6succeeds while APM's ``requests`` calls fail on the same chain. This routes 

7``requests`` through the OS store via ``truststore`` so the two agree, with no 

8per-shell config. 

9 

10Best-effort -- ``configure_tls_trust`` never raises: 

11 

12* An explicit ``REQUESTS_CA_BUNDLE`` / ``CURL_CA_BUNDLE`` wins (no injection). 

13* Missing ``truststore`` or a failed injection falls back to ``certifi``. 

14* ``APM_DISABLE_TRUSTSTORE`` forces the legacy ``certifi``-only behaviour. 

15 

16Child runtimes are Python/CLI subprocesses spawned after ``exec``; the parent 

17cannot monkeypatch their ``ssl`` module. Trust is delivered to the Python 

18``llm`` runtime at venv-setup time: :func:`ensure_child_tls_bootstrap` drops a 

19self-contained ``.pth`` bootstrap into the runtime venv's site-packages so its 

20interpreter injects ``truststore`` at startup with no ``apm_cli`` dependency and 

21no ``PYTHONPATH`` mutation (which would shadow a user ``sitecustomize.py``). 

22:func:`build_child_tls_env` is now an env-hygiene pass only. Node (Copilot) and 

23Rust (Codex) runtimes verify against their own default trust for now (#2034). 

24"""

319def build_child_tls_env(base_env: Mapping[str, str]) -> dict[str, str]: 

320 """Return a copy of *base_env* scrubbed for a spawned child runtime. 

321 

322 Trust is now delivered at venv-setup time via the ``.pth`` bootstrap 

323 (:func:`ensure_child_tls_bootstrap`), NOT at spawn time via ``PYTHONPATH`` 

324 -- prepending a shim dir would shadow a user/corporate ``sitecustomize.py`` 

325 and only reached children that shared this process's ``sys.path``. 

326 

327 This function is an env-hygiene pass: 

328 

329 * strips the internal bundled-default marker so the frozen binary's 

330 ``SSL_CERT_FILE`` marker never leaks into a child, and 

331 * drops ``SSL_CERT_FILE`` WHEN it points at the bundled certifi set, so the 

332 child's ``truststore`` reaches the OS store on Linux (where truststore 

333 honours ``SSL_CERT_FILE``). A frozen parent whose injection failed 

334 restores ``SSL_CERT_FILE=certifi`` and would otherwise leak it, pinning 

335 the child to certifi instead of the OS store. A GENUINE user 

336 ``SSL_CERT_FILE`` is preserved -- only the bundled default is dropped. 

337 """ 

338 child = dict(base_env) 

339 child.pop(_BUNDLED_CERT_MARKER, None) 

340 cert_file = child.get(_SSL_CERT_FILE_VAR) 

341 if cert_file and _is_bundled_certifi(cert_file): 

342 child.pop(_SSL_CERT_FILE_VAR, None) 

343 return child
